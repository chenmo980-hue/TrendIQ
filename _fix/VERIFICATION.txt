## 二、为什么 Node 能连 WPF 不能连

Node 走自带的 OpenSSL。WPF 进程走 .NET HttpClient，TLS 由系统 schannel 负责。
本会话沙箱里 schannel 报 Win32Exception "安全包中没有可用的凭证" (SEC_E_NO_CREDENTIALS 0x8009030E)。
这是 .NET HttpClient 在受限环境下的硬伤——即使把 SocketsHttpHandler.UseProxy 设为 false 也不绕开。

诊断文件（dist\\diag.txt）实测抓到的堆栈：
  type:   System.Net.Http.HttpRequestException
  message: The SSL connection could not be established, see inner exception.
  inner:   System.Security.Authentication.AuthenticationException :: Authentication failed, see inner exception.
  inner:   System.ComponentModel.Win32Exception :: 安全包中没有可用的凭证
  stack:  EstablishSslConnectionAsync -> ConnectAsync -> HttpConnectionPool ...
  env HTTP_PROXY=http://127.0.0.1:7897 HTTPS_PROXY=http://127.0.0.1:7897

**用户在自己桌面双击时不会继承 https_proxy，但 schannel 受限问题同样可能在受控/企业环境出现。**

## 三、本轮代码改动

- HttpClient 改用 SocketsHttpHandler { UseProxy = false }，不再受 HTTPS_PROXY 拖入 schannel 失败链。
- 构造函数末尾通过 Dispatcher.BeginInvoke 启动即拉一次模型列表，下拉立即有内容。
- FetchModelsAsync / SendMessageAsync 失败时把 inner exception 与堆栈追加写入 dist\\diag.txt，
  状态栏显示 "拉取失败：<inner type> :: <inner message>"，用户能直接看到根因。
- 上一轮的配置读取修复（多路径打分 + 镜像保存）保留，本轮未动。
