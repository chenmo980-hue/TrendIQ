## 一、修复的问题

### 问题 1：配置能保存、读取不了（用户原话："可以保存配置，但是读取不了配置"）

根因（实测坐实，非推断）：
1. 应用启动时用"写探针"选可写目录。本机 %APPDATA% 在受限环境返回 UnauthorizedAccessException，
   写路径因此漂移到程序目录 dist\config。
2. 旧 Load() 只认这**一个**路径，且逻辑是"文件存在就返回"。
   dist\config\settings.json 里恰好躺着一份**旧配置**（BaseUrl=https://kktoken.cc/v1，ApiKey 为空），
   于是每次启动都读到这份空配置，用户真正填好的 %APPDATA% 那份永远被挡在后面。
   → 表现就是"保存成功、下次打开什么都没有"。

修复：
- SettingsStore.Load()：把所有候选路径全部解析出来，按内容完整度打分（密钥 +4、网址 +2、模型 +1），取最高分那份。
- SettingsStore.Save()：写主路径的同时，把其余**已存在**的候选文件一起刷新成同一内容，消除分叉。
- MainViewModel.LoadSettings()：找不到配置时状态栏明说"未找到历史配置"；找到时显示真实来源路径。

### 问题 2：400 与超时提示完全一样（用户原话："这不对"）

根因：所有非 2xx 响应被压成一个 HttpRequestException，界面统一渲染成
"诊断：请求未完成 / HTTP xxx / 请检查 API 基本网址、密钥、模型 ID 与网络连接。"
快速 400（模型无通道）与 90 秒挂死（通道卡在调度）看起来一模一样。

修复：
- SendAsync 把服务端正文里的 error.message 一并带出，界面不再只剩一个光秃秃状态码。
- RenderError 按状态码分级：400/401/403/404/503/522 各自给出具体含义，超时单独一段并提示换模型。
- HttpClient 超时从 90s 降到 30s，死通道不再白等一分半。
